# שרת הסנכרון של אוצר שלמה

`yanuka-server` הוא קובץ הרצה אחד, קטן, שמחזיק עותק של המאגר ומעביר שינויים
בין המכשירים המצומדים אליו (ADR-039, [`docs/SYNC.md`](../docs/SYNC.md)).
הוא **לא** חובה: מחשב בודד עובד בלעדיו בדיוק כמו קודם. מקימים אותו כשרוצים
שמחשב שני (או בעתיד — דפדפן וטלפון) יראה את אותו מאגר.

מה הוא עושה, ומה לא:

- מקבל שינויים ממכשיר מצומד ומעביר אותם לשאר — שדה אחרי שדה.
- מסרב לשינוי שנעשה על גרסה ישנה; המכשיר ממזג ושולח שוב. השרת עצמו **לא
  ממזג** ולא מכריע בהתנגשויות — זה נעשה במכשיר, מול האדם.
- לא מתקין שום דבר משלו (גם לא את הקטגוריות המובנות). מה שיש בו הוא מה
  שהמכשירים סיפרו לו.
- העותק שלו הוא מאגר אמיתי, עם חיפוש — הבסיס לגרסת הדפדפן שתבוא.

## הרצה

```sh
# בניה (Rust; מכל מקום — אין תלות ב-Tauri או ב-webview)
cargo build --release -p yanuka-server
# ההרצה
./target/release/yanuka-server
```

בהפעלה הראשונה השרת מדפיס **קוד צימוד**:

```
אוצר שלמה server 0.10.0 — אוצר שלמה — data in data
0 paired device(s); listening on http://0.0.0.0:8787

  קוד צימוד למכשיר חדש:   K7PT-4MXQ
  תקף עד:                 2026-09-07T12:15:00Z
```

במחשב: הגדרות ← **סנכרון בין מכשירים** ← כתובת השרת (למשל
`http://192.168.1.10:8787`) והקוד ← "צימוד וסנכרון ראשון". המאגר עולה
לשרת בסבב הראשון. למכשיר הבא לוחצים באותו מסך "קוד למכשיר נוסף" — או
מריצים בשרת `yanuka-server pair-code`. קוד תקף רבע שעה, לשימוש חד־פעמי.

הגדרות, כולן ממשתני סביבה:

| משתנה | ברירת מחדל | תפקיד |
|---|---|---|
| `YANUKA_DATA_DIR` | `data` | היכן נשמר `otzar-shlomo.db` |
| `YANUKA_BIND` | `0.0.0.0:8787` | כתובת ופורט להאזנה |
| `YANUKA_SERVER_NAME` | `אוצר שלמה` | השם שמוצג במכשירים |
| `YANUKA_DB_KEY` | — | מפתח הצפנה (64 ספרות hex), רק בבנייה עם `--features sqlcipher` |

פקודות נוספות:

```sh
yanuka-server pair-code        # קוד צימוד חדש
yanuka-server devices          # המכשירים המצומדים ומתי נראו לאחרונה
yanuka-server revoke <id>      # ניתוק מכשיר (הרשומות שלו נשארות)
yanuka-server backup <file>    # עותק עקבי של המאגר
```

## איפה מריצים — שלוש צורות

**1. ברשת הביתית / המשרדית (הפשוט ביותר).** מריצים על המחשב המרכזי עצמו,
על מחשב שני שדולק, על NAS או על Raspberry Pi. המכשירים מגיעים בכתובת
הפנימית (`http://192.168.x.x:8787`). התעבורה לא יוצאת מהרשת; אין צורך
ב-HTTPS. מחוץ לבית — דרך VPN של הראוטר, או רשת פרטית כמו Tailscale, שמאפשרת
לפנות לשרת מכל מקום בלי לפתוח פורט לעולם.

**2. שרת קטן באינטרנט (VPS), מאחורי Caddy.** לשרת עצמו אין TLS בכוונה; שמים
לפניו reverse proxy שמנפיק תעודה לבד:

```
# Caddyfile
otzar.example.com {
    reverse_proxy 127.0.0.1:8787
}
```

ומאזינים רק מקומית: `YANUKA_BIND=127.0.0.1:8787`. במכשירים מזינים
`https://otzar.example.com`. עלות: VPS הזול ביותר מספיק בהרבה — המאגר קטן
והתעבורה זניחה.

**3. Docker.**

```sh
docker build -t yanuka-server -f server/Dockerfile .
docker run -d --name otzar -p 8787:8787 -v otzar-data:/data yanuka-server
docker logs otzar          # קוד הצימוד הראשון
docker exec otzar yanuka-server pair-code
```

## גיבוי

הכול בקובץ אחד, `otzar-shlomo.db`, בתיקיית הנתונים. `yanuka-server backup
<file>` מייצר עותק עקבי בזמן שהשרת רץ. וגם בלי זה — כל מכשיר מצומד מחזיק
עותק מלא של המאגר: אובדן השרת אינו אובדן מידע. מקימים שרת חדש, מצמדים
מכשיר, והמאגר עולה מחדש.

## אבטחה, בקצרה

- כל מכשיר מזדהה באסימון שנוצר בצימוד; בשרת נשמר רק ה-SHA-256 שלו (וכך גם
  של קודי הצימוד). עותק של קובץ השרת לא מאפשר להתחבר בשמו של אף מכשיר.
- ניתוק מכשיר שאבד: `yanuka-server revoke <id>` (המזהה ב-`devices`), או
  מכל מכשיר אחר דרך ה-API.
- הצפנה במנוחה לעותק של השרת: בונים עם `--features sqlcipher` ומגדירים
  `YANUKA_DB_KEY`. ברירת המחדל היא ללא הצפנה — ברשת פרטית זה בדרך כלל
  מספיק, ובשרת ציבורי מומלץ להפעיל.
- ראו [`docs/SECURITY.md`](../docs/SECURITY.md).

## ה-API

כל הנתיבים תחת `/api`, JSON. פרט ל-`health` ול-`pair`, כולם דורשים
`Authorization: Bearer <token>`.

| | |
|---|---|
| `GET /api/health` | שם השרת וגרסתו |
| `POST /api/pair` | `{code, device}` → `{token, serverName, deviceId}` |
| `POST /api/pair-codes` | קוד צימוד חדש |
| `POST /api/sync/push` | `{items: [revision…]}` → `{results: [...]}` |
| `GET /api/sync/pull?after=&limit=` | דף מהזרם, בלי השינויים של המכשיר הפונה |
| `GET /api/status` | מונים: אנשי קשר, מכשירים, ראש הזרם |
| `GET /api/devices` | המכשירים המצומדים |
| `POST /api/devices/{id}/revoke` | ניתוק מכשיר (לא את עצמך) |

מבנה ה-revision והמיזוג מתוארים ב-[`docs/SYNC.md`](../docs/SYNC.md).
