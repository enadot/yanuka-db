# VERSIONING

## איך קוראים מספר גרסה

`0.2.0` הוא **שלושה מספרים** מופרדים בנקודות — לא שבר עשרוני:

```
0 . 2 . 0
│   │   └─ patch — תיקון באג בלבד, שום יכולת חדשה
│   └───── minor — יכולת חדשה (שלב מוצרי שהושלם)
└───────── major — 0 כל עוד המוצר בהרצה; 1 מרגע שהוא הכלי היומיומי
```

אין דבר כזה `0.01`. ואין כאן חשבון עשרוני: אחרי `0.9.0` באה `0.10.0`,
והיא *גדולה* ממנה. זהו התקן המקובל (Semantic Versioning) וכל כלי הבנייה
מניחים אותו.

## המדיניות בפרויקט הזה

- **כל שלב מוצרי שמושלם מעלה את ה־minor.** ייבוא CSV, מיזוג כפילויות,
  גיבויים — כל אחד כזה הוא `0.x.0` חדש. ההעלאה נעשית בקומיט האחרון של
  השלב, כך שהמתקין שנבנה ממנו כבר נושא את המספר החדש.
- **תיקון שנשלח בין שלבים מעלה את ה־patch** (`0.2.1`).
- **`1.0.0` היא החלטה מוצרית, לא טכנית**: הרגע שבו המחשב המרכזי עובד עם
  התוכנה על הארכיון האמיתי ביומיום. עד אז ה־major נשאר 0, וזה בסדר גמור —
  משמעותו "המבנה עוד רשאי להשתנות".

## איפה המספר חי, ואיך מעדכנים

הגרסה מוצהרת בארבעה קבצים שחייבים להסכים זה עם זה:

| קובץ | מי קורא אותו |
|---|---|
| `apps/desktop/src-tauri/tauri.conf.json` | שם קובץ ההתקנה: `Contacts_0.2.0_x64-setup.exe` |
| `apps/desktop/package.json` | מסך ההגדרות מציג ממנו את הגרסה |
| `package.json` (שורש) | זהות המונורפו |
| `Cargo.toml` (שורש, `[workspace.package]`) | כל קרייטי ה־Rust יורשים ממנו |

לעולם לא עורכים אותם ביד. במקום זה:

```sh
node scripts/set-version.mjs 0.3.0
cargo update --workspace        # מרענן את Cargo.lock
```

מבחן (`apps/desktop/src/version.test.ts`) מפיל את הצינור אם הקבצים
התפצלו — עריכה ידנית ששכחה קובץ אחד לא עוברת CI.

## איך יודעים איזו גרסה מותקנת

הגדרות ← בתחתית המסך: "מאגר הקשרים · גרסה 0.2.0". שם הקובץ שהותקן ממנו
נושא את אותו מספר. במכונה ללא אינטרנט זה כל סיפור העדכון: משווים את המספר
שעל המסך למספר שעל קובץ ההתקנה שבידך, ואם הקובץ חדש יותר — מתקינים אותו
מעל הקיים (הנתונים אינם נגעים; ראו ADR-021).
